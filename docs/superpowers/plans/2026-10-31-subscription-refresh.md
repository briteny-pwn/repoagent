# 订阅刷新作为设置操作

目标：刷新订阅只下载和更新节点，不创建任务、不跳转任务页、不启用代理。

实现：POST /api/settings/subscription/refresh 改为异步 HTTP 操作，40 秒总超时，应用内互斥防止重复刷新；返回脱敏 settings。下载成功后在事务中校验 URL 与凭证代数仍匹配，再更新节点、刷新时间和状态，保留网络及当前启用节点。失败不覆盖旧数据。无需模型或 Mihomo。

步骤：
1. API 回归测试：成功没有任务、失败保留节点、撤销/替换 URL 阻止晚到结果、旧任务列表排除。
2. Worker 拒绝执行旧 subscription 任务，保留历史记录；节点启用前检查节点列表没有被刷新覆盖。
3. 前端 refreshSubscription 返回 Settings；按钮显示刷新中、重复点击禁用，结果留在设置页；API 客户端测试和浏览器验证。
4. 更新接口/使用文档；后端测试、前端测试/构建、独立审查、PR、试用部署和版本记录。

边界：这次只调整订阅刷新。节点测试启用仍沿用现有后台流程；网络诊断不在此次修改范围。首次刷新仍依赖可达且有效的 HTTPS 订阅源。
