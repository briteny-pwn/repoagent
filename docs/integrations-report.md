# External adapter implementation report

The adapters implement the public GitHub read tools and confirmed issue/comment publication interface in `docs/api-contract.md`. GitHub reads use at most two pages of 50 items for list tools and at most three attempts for transient GET failures. Responses report coverage. `read_file` decodes UTF-8 text, returns at most 200 KiB with truncation coverage, and rejects binary files. POSTs run once; uncertain network, timeout, and server failures surface as `IntegrationError(ambiguous=True)` for worker reconciliation. A `before_write` callback runs immediately before POST after read-only preflight, allowing the worker to recheck cancellation and authorization. Comments require an open issue target and reject pull requests. Rate limit errors carry an epoch retry time. HTTP redirects are rejected, and errors omit remote response bodies and credential-bearing URLs.

The model adapter sends OpenAI-compatible chat completions with `max_tokens: 4096` and preserves assistant tool calls. Real model and subscription URLs require HTTPS and public DNS resolution before use; custom HTTPS ports are allowed. Each request connects to a validated public IP while preserving the original Host header and TLS SNI name. This also prevents a configured HTTP proxy from resolving the destination hostname to a different address. The model adapter does not follow redirects and uses a 60-second timeout. All HTTP clients ignore ambient proxy environment variables so direct mode stays direct. Deployment should still apply outbound firewall controls, including to the Mihomo sidecar and fixed GitHub API endpoint.

Subscription import accepts Clash YAML `proxies` lists and base64 or plain URI lists with Trojan, Shadowsocks, and VMess nodes. Supported Shadowsocks ciphers are AES-128/192/256-GCM, ChaCha20-IETF-Poly1305, and XChaCha20-IETF-Poly1305. VMess supports TCP and WebSocket paths. Unsupported protocols and unsafe VMess WebSocket options are rejected; unrecognized per-node fields and top-level rules, listeners, controller settings, and scripts are discarded. Before real sidecar activation, node hostnames resolve to public IPs and the generated config pins those IPs while preserving Trojan/VMess TLS server names. Subscription download is limited to 2 MiB, uses a 30-second timeout, and rejects redirects.

Mihomo config rendering emits only fixed local listener/controller settings, a `PROXY` selector, and `MATCH,PROXY`. Activation requires an explicitly configured internal controller and proxy URL plus an existing generated safe baseline. It atomically writes a candidate, loads it, selects the node, probes GitHub through the proxy, and runs the worker's `before_commit` callback inside rollback protection. Failure restores the previous file and reloads the controller, then checks `/configs` and `/proxies`; a failed or unverified restore raises a distinct rollback error. `deactivate_mihomo` loads a direct baseline that removes stored node credentials. The controller URL is restricted to `localhost`, `127.0.0.1`, or `mihomo` over HTTP. The deployment must share the generated config path with the sidecar controller and initialize it before activation.

Verification: `PYTHONPATH=backend .venv/bin/pytest -q backend/tests/test_integrations.py` — 43 passed. Full backend suite — 73 passed with one Starlette deprecation warning. Tests use HTTP mock transports; no real subscription, credential, model, or GitHub write was used.
